# Проект 1 — Планировщик учебного сервера

## Цель проекта

Изучить алгоритмы планирования процессов в операционных системах и сравнить их эффективность.

## Используемые технологии

- Ubuntu / WSL2
- Python 3.14
- VS Code

## Реализованные алгоритмы

1. FCFS — процессы выполняются в порядке поступления.
2. SJF — первым выбирается процесс с минимальным временем выполнения.
3. Round Robin — каждый процесс получает ограниченный квант процессорного времени.
4. Priority — процессы выбираются по приоритету. Чем меньше число, тем выше приоритет.
5. Priority Aging — приоритет ожидающего процесса постепенно повышается.

## Наборы данных

- `set1.txt` — 4 процесса.
- `jobs.txt` — 6 процессов.
- `mixed.txt` — 18 процессов.
- `starve.txt` — 20 процессов.

## Результаты основного набора jobs.txt

| Алгоритм | Среднее ожидание | Средний Turnaround |
|---|---:|---:|
| FCFS | 7.50 | 11.33 |
| SJF | 5.17 | 9.00 |
| Round Robin q=2 | 8.33 | 12.17 |
| Priority | 7.67 | 11.50 |

На этом наборе минимальное среднее время ожидания показал SJF.

## Исследование смешанной нагрузки

На `mixed.txt` FCFS показал среднее ожидание 93.28, а Round Robin с квантом 2 — 30.83.

Это объясняется тем, что FCFS заставляет короткие процессы ожидать завершения длинных задач, а Round Robin распределяет процессорное время между процессами.

## Проблема голодания

На `starve.txt` процесс P1 ожидает 57 единиц времени при Priority.

При этом среднее время ожидания всех процессов составляет всего 2.85. Следовательно, средние показатели не отражают проблемы отдельных процессов.

Для исследования решения этой проблемы реализован механизм Aging, который постепенно повышает приоритет ожидающих процессов.

## Вывод

В ходе проекта реализованы четыре алгоритма планирования и проведено их сравнение.

SJF часто уменьшает среднее время ожидания, но может приводить к длительному ожиданию отдельных процессов.

Round Robin обеспечивает регулярное распределение процессорного времени, однако результаты зависят от выбранного кванта.

Priority позволяет учитывать важность задач, но без дополнительных механизмов некоторые процессы могут долго ожидать.

Выбор алгоритма зависит от характера нагрузки и требований системы.
